## 对求解器的含义

1. **主目标是时间，不是建筑数**：交付时间 = 需求量 / 产线额定速度；图纸与 BOM 是为这个时间服务的。
2. **不过河拆桥**：旧的形状产线可以继续为升级供货，所以战役图共用一张地图和一个中心，不默认拆旧厂。
3. **平衡器前后拓扑不同**：L4 之前不能分叉/汇合，扇出只能复制源或多拉几条带；L4 之后才能分叉，而中心始终只有 16 个入口格。
4. **中心入口有限，但多喂不阻塞**：超产直接送中心没有副作用，所以不需要精确配平——这是求解器不做产线平衡的依据。
5. **矿脉是有损的**：采矿机必须留出口，矿脉边缘的格子会浪费；`scanMap`/`scanForTypes` 只按可达矿脉估算，不把矿脉形状当精确资源。
6. **工程效率是下一层**：当前 `rates.ts` 只给额定速度（传送带 2/s、采矿机 0.4/s、色料源 0.4/s，升级 1），不建模带速升级、机器节拍、堆叠与拥堵。

## 这是 NP 问题吗

不是严格意义上的「NP 完全」——仓库里没有归约证明，也不该凭感觉下这个结论。可以拆成两层看：

- **单图形状分解**（当前求解器真正解的部分）：层数 ≤4、象限 4 个，状态空间有限；`planShape` 是带预算的深度优先搜索，每个候选都用真实的 `S.stack`/`S.cut`/`S.paint` 重放，`verifyPlan` 再复算一遍。这是**有界组合搜索**，可判定、可验证，规模靠 `maxAttempts`/`splitCap` 控制。
- **整条战役的时间最优**（含产线复用、核心入口、平衡器/隧道拓扑）：这是**调度/资源分配**问题（连续时间、资源近似无限、入口有限），比单形状分解大一层。当前求解器没有解这一层，只给出每种形状的独立产线 + 额定速度 ETA。

所以：**现在是「已验证的单形状组合搜索 + 未建模的战役调度」**，不是「已经证明的 NP 问题」。

**补充（2026-11-16）**：优解的形式定义见 `docs/adr/0001-optimal-plan-pareto.md`——交付效率（送入中心/秒）与占用格的帕累托前沿；交付上限 = 中心入口 × 带速（16 × 2 = 32/s）。这把上面的「主目标是时间，不是建筑数」落成两轴判据；`cost` 只作搜索标量。
